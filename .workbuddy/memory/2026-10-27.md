- 新增 `packages/sandbox/src/providers/bubblewrap.ts`：`buildBubblewrapPlan()` 生成 argv；`probeBubblewrap()` 用**同一个 runner** 真实启动 `/bin/true`，并校验回报的 `program === bwrapPath`。只检测二进制存在**不**作为能力依据。
- 重写 `os-sandbox-provider.ts`：`isAvailable()` 只认探针通过；新增 `execUntrusted()` 真经 bwrap 启动目标程序，三层溯源校验（program 是 bwrap、无 spawnError、stderr 无 `bwrap:` setup 错误）；非 Linux / 无 bwrap / 探针失败 / 执行器缺失全部 fail closed，不降级。
- `capability-detector.ts` 去掉 `existsSync('/proc')` 的 Linux 猜测放行；`sandbox-manager.ts` 对 `trustLevel: untrusted` 与 `type: os_sandbox` 强制走 OS 沙箱并校验 `isolation` 溯源；`sandbox-lifecycle.ts` 删掉 `runInSandbox()` 这条绕过路径；`resource-limiter.ts` 注释明确"不是隔离边界"。
- CLI：新增 `forgex sandbox [--json]`（`apps/cli/src/commands/sandbox.ts`），doctor 增加沙箱项；`docs/SECURITY.md` 第 8 节重写为三层能力表 + 实测记录表。

## 关键经验

- Windows 本机没有 bwrap/WSL，真实隔离效果只能走远程验证：`npx esbuild <script>.mjs --bundle --platform=node --format=esm --target=node18 --external:ssh2 --external:cpu-features` 打包后 `scp` 到远端 `/tmp`，远端需放 `ssh2` stub（`/tmp/node_modules/ssh2`）。
- 该主机可免密 `ssh pms@172.16.1.210`（密钥登录），无需 sshpass。
- `ps -eo comm` 统计泄漏不可靠（宿主有无关 `sleep 180` 进程）；要用唯一参数（如 `sleep 400`）+ 精确匹配，或 kill 前后对比。

### 评测发现的真实产品缺陷（已修）

- `packages/tools/src/execution/process-runner.ts`：Node ≥18.20 禁止直接 `spawn('npm.cmd')`（CVE-2024-27980 缓解）→ Windows 上质量门禁必然 `spawn EINVAL`。修法：`.cmd/.bat` 经 `cmd.exe /d /s /c "…"` 执行、`windowsVerbatimArguments: true`，并在**子进程 PATH 自己扫描** PATHEXT 解析绝对路径（父进程 `process.env.PATH` 与实际下发环境不一致时不能依赖 `where`）。配 `packages/tools/test/process-runner.test.ts`。

## 可审阅 Git worktree 隔离（v0.5.6）

- 新增 `apps/cli/src/task-run/review-worktree.ts`：`assertCleanRepo` / `createReviewWorktree` / `readWorktreeDiff` / `removeReviewWorktree` / `assertPathInsideRoot`。全部走真实 git（可注入 `GitRunner` 但生产默认 spawn git）。
- `apps/cli/src/commands/task.ts`：`forgex task list|show|diff|clean`；`run.ts` 新增 `--worktree`（opt-in，默认原地执行不变）。
- 隔离生效方式：创建 worktree 后把 `loaded.config.security.workspaceRoots/writableRoots` **收窄到 worktree 路径**，再建 runtime → 路径校验、审批、审计自然跟着新工作区走；并在审计里写一条 `session` 事件带 `meta.worktreePath/isOsSandbox:false`，用于把相对路径还原成绝对位置。
- 持久化：`task_runs` 新增 `isolation/worktree_root/worktree_path/worktree_branch/base_commit`，构造器里按 `PRAGMA table_info` 做增量迁移。
- 关键坑：
  1. `task_runs.session_id` 有外键指向 `sessions(id)`，**全新库先插入会报 `no such table: main.sessions`**。现在 run.ts 先 `new SessionStore(dbPath)` 建 schema 再开 TaskRunStore。
  2. worktree 必须建在仓库**外**（默认 `~/.forgex/worktrees`），否则 `git status` 会看到未跟踪目录、快照断言也会被污染。
  3. `task clean` 默认拒绝删除有未提交改动的 worktree，必须 `--force`；e2e 里要带上。
  4. Windows `core.autocrlf` 会把 checkout 转 CRLF，断言文件内容前要统一换行；`git worktree list` 输出用正斜杠，比较前要归一。
- 测试：`apps/cli/test/review-worktree.test.ts` 22 passed / 1 skipped（symlink，Windows 无权限），真跑 git；eval 新增 T11–T11e（成功/脏仓库拒绝/门禁失败保留/路径越界/强杀保留），全套 **26 场景 24 通过 2 跳过，断言 173/173**，全量单测 **943 passed / 10 skipped**，`tsc -b` 通过。
